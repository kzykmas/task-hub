# 仕様書 v1.0 — タスクノートとボードの確定仕様

対象読者：増野さんと秘書AI。`docs/タスクノートの書き方.md` の後継。
基準：タグ `v1.0-pre-refactor-20260818` 時点の `scripts/` の挙動が正。
経緯・決定の理由は `docs/経緯_タスク管理システム.md` を見る。本書は**現在形の仕様だけ**を書く。

## 1. front matter の全キー

`tasks/*.md` の先頭 `---` ブロック。**ここに無いキーは増やさない。**

| キー | 値 | 挙動・効く場所 |
|---|---|---|
| `id` | `GONO-130` 等 | 接頭辞＋3桁。人は振らない（→§4 採番） |
| `org` | 郷野の郷 / 構想P / STREAM / 安全学校 / AI改善 / 家族・個人 | 団体色・団体別ボードの束ね |
| `title` | 文 | タスク名。全角15文字以内が目安（→§6 命名） |
| `short` | 短縮名 | タイムラインのラベル・親参照（⟵）で `title` より優先 |
| `status` | 7語のみ（→§2） | 節の振り分けの基本 |
| `role` | `do` / `monitor` | `monitor` は「監視の期日」担当。無印＝`do` |
| `due` | `2026/08/31` | 期日。節の振り分け・色・並び順の基準 |
| `size` | `light` のみ | 軽タスク（1時間未満）。無印＝重（1時間以上） |
| `labor` | `physical` | 肉体作業。💪 マーク。負荷ボックスで件数表示 |
| `timebound` | `true` | 日時変更不可の拘束。「2週間ある」に出て、至急・1週間枠・期限アラートから除外 |
| `undated` | `true` | 拘束だが日付未定。「2週間ある」下の注記に出る |
| `urgent` | `true` / 日付 | `true`＝恒常的に至急、日付＝その日だけ至急（明日への先送りに使える） |
| `today` | 日付 | その日にやるつもり。「🎯 今日やるつもり」。翌日には自動で外れる |
| `later` | `true` のみ | 「あとで」チップ。団体別ボードの期限順から外れ非表示件数に数える。**`true` 以外は無視** |
| `reason` | `法令期限` `安全` `資金` の3語のみ | 色付きチップ（法令期限＝明紫 `#a855c7`）。他の語は表示されない |
| `parent` | `KOSO-001` 等 | 親のID。親の行の下に子行で展開（完了した子は展開しない） |
| `lead` | `3d` | 親の `due` から逆算して自分の `due` を**上書き**。↩ マーク付き。逆算切れは警告 |
| `owner` | 人名 | 相手の作業。担当チップ・タイムラインの破線ボックス |
| `asked` | 日付 | 依頼日。「⏳待ちN日」の起点。未記入だと**赤字「未依頼」** |
| `next_check` | 日付 | `role: monitor` 用。7日以内なら「監視の期日」に出る。確認したら先へ進める |
| `check_cycle` | `monthly` / `weekly` / `daily` | 見回り周期。`daily` は1週間枠・期限アラートから除外（監視の期日で毎朝見る） |
| `wait` | `important` / `light` | `waiting` の重要度。無印＝自動判定（期限7日以内で重要） |
| `pin` | `true` | タイムラインの最上位に固定（例：GONO-006 の法令期限） |
| `after` | `GONO-009` / カンマ区切り複数 | 前工程のID。タイムラインの矢印 |
| `src_no` | `A-06` 等 | 元台帳番号。あればIDの代わりに表示 |
| `category` / `category_name` | `A`〜`H` / 運営手続き 等 | 元台帳の分類。表示には使わない |
| `project` | フォルダ名 | 関連する企画フォルダ。表示には使わない |
| `created` / `done_date` | 日付 | 起票日／完了日 |

本文は `## 概要` `## 経緯` を基本に、必要なら `## 要確認` `## 完了`。
経緯には**日付と誰の指示か**を書く（例：`- 2026/08/14 増野さん報告により完了`）。

## 2. status の7語

| 値 | 挙動 |
|---|---|
| `todo` | 既定。期限アラート・団体別ボードに出る |
| `this_week` | 「これから1週間でやる」への手動指定。**期限の無いもの**を枠に入れるときだけ使う（期限3日以内は自動で入る）。団体別ボードの期限順からは外れる |
| `doing` | 仕掛かり中。節は作らず行の左に 🚧。集計上は `todo` と同じ |
| `research` | 事前調査（仕掛かる前の壁打ち・整理）。🔍。集計上は `todo` と同じ。着手を進捗に水増ししないため `doing` と分ける |
| `waiting` | 相手の作業・納品待ち。期限アラート・至急・1週間枠に出さず「👥 待ち」節へ |
| `done` | 全集計から外れる。月次で `archive/YYYY-MM/` へ |
| `dropped` | 読み込み時点で除外 |

## 3. ボードの節構成（上から順）

HTML（`board/index.html`）の節と入る条件。md版（`board/taskboard.md`）は節順が一部異なる
（負荷・2週間あるが後方）が、振り分けロジックは同一。

| 節 | 入る条件 |
|---|---|
| 📅 2週間ある | ★付き予定（`config/fixed.json`）＋ `timebound: true` かつ `due` が14日以内の未完タスク。`undated` は注記 |
| 📊 今週の負荷 | 「これから1週間でやる」を重=1・軽=0.5で合算。基準7。5未満リラックス／5〜7正常／7超注意／10超警戒 |
| 🚨 至急 — 今日やる | `done` `waiting` 以外・非拘束で、`due` が今日 または `urgent` が `true`／今日の日付 |
| 🎯 今日やるつもり | `done` `dropped` 以外で `today` が今日 |
| 👥 待ち | `status: waiting` 全件。重要／軽度に分ける（→§7） |
| ⭐ これから1週間でやる（重／軽） | →§5。`size: light` が軽、無印が重 |
| ⏰ 期限アラート | `due` 持ちで期限切れ／3日以内／14日以内。`waiting` `timebound` `check_cycle: daily` は除外 |
| 👀 監視の期日 | `role: monitor` で `next_check` が7日以内（過ぎたものを含む） |
| 📐 タイムライン | 細目（子）を持ち未完の親のうち、親か子の最遅期日が今日から150日以内。`pin: true` が最上位、以下期日順 |
| 🗂 団体別ボード | 団体ごとに：期限の近い順上位8件（`parent` 持ち・`monitor`・`this_week`・`later` を除く）＋バックログ（期限なし）＋監視中（6件まで）。溢れは「非表示: 期限が先のもの N件」 |

### 重複排除

1つのタスクは **至急 → 今日やるつもり → 待ち → 1週間（重）→ 1週間（軽）→ 期限アラート → 監視の期日**
の順で、**最初に該当した1節にだけ**出る。省かれた分は見出し脇に「（＋上の節にN件）」。

- **対象外**：「2週間ある」（カレンダー＝事実の枠）、「タイムライン」「団体別ボード」（俯瞰の場所）
- 「これから1週間でやる」の件数（N/7）は**枠の総数のまま**。重複排除で減らない
- 期限アラートの「期限切れ」「3日以内」は1週間枠と完全に重なるため実質空になる。残るのは
  主に4〜14日先のものと、枠に入らない `role: monitor` の近い期限

## 4. 採番

1. `config/numbering.json` の該当接頭辞の `last` を読む
2. +1 した番号でファイルを作る（`<接頭辞>-<3桁>_<タイトル>.md`）
3. `last` を更新する
4. **以上を1コミットで行う**。push が reject されたら pull --rebase 後に採番し直す

接頭辞：AIW（AI改善）／GONO（郷野の郷）／STRM（STREAM）／KOSO（構想P）／ANZN（安全学校）／ME（家族・個人）。
ID重複を直すときは「番号の若い方を残す」より**生きているタスクのIDを変えない**を優先。
退避は削除せず `_to_delete/<理由>_YYYYMMDD/` へ。

## 5. 「これから1週間でやる」の入り方

**期限が3日以内（期限切れを含む）のタスクは自動で入る。** 手動は `status: this_week`（期限不問）。

    期限3日以内 → 自動で「これから1週間でやる」
        ↓ その中から自分で選ぶ
    today: 今日の日付 → 🎯 今日やるつもり
        ↓ 期限が今日のものは必ず
    🚨 至急

自動で入らないもの（別の場所で見る）：

| 除外 | どこで見るか |
|---|---|
| `timebound: true` | 📅 2週間ある |
| `role: monitor` | 👀 監視の期日 |
| `check_cycle: daily` | 👀 監視の期日 |
| `status: waiting` | 👥 待ち |
| `done` / `dropped` | 出ない |

**期限が無いタスクは自動で入らない。** 枠に入れたいときだけ `this_week` を書く。

### 7枚は上限ではなく「見直しの合図」

重7枚（軽は10件目安）を超えると赤い警告が出る。**超過は止めるものではなく期限を見直すきっかけ**。
動かせる期日を先へずらす／相手に振れるものは `owner` を付ける、といった判断をする。

## 6. 命名

- **タスク名は全角15文字以内**が目安。超えるなら `short` を付ける
  （`short` はタイムラインのラベルと親参照で使われる。一覧行は `title` を画面幅で `…` 省略し、
  全文はマウスオン／長押しで出る）
- **行為ではなく成果で名付ける**。往復するタスク（連絡→回答待ち→確認…）は
  ✗「〜の税理士連絡」→ ○「第2期決算の確定（税理士とのやり取り）」（GONO-130）。
  あわせて `owner` と `asked` を書けば「⏳依頼済み・待ちN日目」が自動で出る
- 補足はタスク名に詰め込まず本文の `## 概要` へ

## 7. 待ちの重要度

「👥 待ち」は毎朝まずチェックする節。中を重要／軽度に分けて見た目のトーンを変える。

| 指定 | 挙動 |
|---|---|
| `wait: important` | 常に重要 |
| `wait: light` | 常に軽度 |
| 無印 | **期限の1週間前を切ったら重要**、それより先（期限なしを含む）は軽度 |

## 8. 日次見回り（check_cycle: daily）

開催直前の集客チェック等、**毎日見るもの**。`due` は「毎日やるのを終える日」であって締切ではない。
「監視の期日」に出続け、確認したら `next_check` を翌日へ進める。
期限アラート・1週間枠には出ない。

## 9. タイムライン（ガント）の見方

各タスクは**期日の1日分のボックス**、`after` の依存が**矢印**でつながる。

- ★＋太枠＝そのタイムラインのゴール（親タスク自身）
- ◆＝拘束（`timebound`。「日付未定」は `undated`）
- 破線ボックス＝相手の作業（`owner`）。右に担当・待ちN日目
- 色は期限の近さ：赤＝期限切れ／橙＝3日以内／黄＝14日以内／青＝先。グレー＝完了・待ち
- 青い縦破線＝今日。`pin: true` が最上位
- 見出しに残子タスク数バッジ（残N/M、全完了なら ✅）

md版は SVG の代わりに「📐 企画の進捗」節で 親・残N/M・次の一手（▸）を1行で出す。

## 10. やってはいけないこと

- 生成物（`board/`）の手編集。直すのは `tasks/` か `scripts/`
- 語彙を勝手に増やす（表に無い `status` `reason` `wait` 等を作らない）
- 入力に無い情報を書く。不足は質問する
- ファイルの削除（`_to_delete/` へ退避する）
