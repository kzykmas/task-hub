# 設計書 v1.0 — システム構成と改修の手引き

対象読者：このシステムを改修する将来のAIセッション。
基準：タグ `v1.0-pre-refactor-20260818`。表示仕様は `docs/仕様書_v1.0.md`、
決定の経緯・採らなかった案は `docs/経緯_タスク管理システム.md` を見る。

## 1. 3層分離

| 層 | 置き場 | 役割 |
|---|---|---|
| 正本 | GitHub `task-hub`（このリポ） | タスクノート・スクリプト・設定。履歴と採番の一意性を git が担保 |
| 配信 | さくら `www/taskboard/` | 生成物のみ。Basic認証で iPhone から閲覧。正本を持たない |
| 知識・資料 | Obsidian Vault | 3端末Sync。タスクの正本は無い。`.git` を置かない |

## 2. 配信パイプライン

```
scripts/update.sh "メッセージ"
  ├ git pull --rebase --autostash        # 未コミット編集が通常状態なので autostash 必須
  ├ python3 scripts/gen_dashboard.py    . <today> board/index.html   config/fixed.json
  ├ python3 scripts/gen_dashboard_md.py . <today> board/taskboard.md config/fixed.json
  ├ 実質無変更なら何もしない              # md版の「生成:」行だけの差分は無視して checkout で戻す
  └ git add -A && git commit && git push (main)
        ↓
.github/workflows/deploy-sakura.yml      # board/** への push で発火
        ↓ FTPS（アップ先 www/taskboard はYAMLに固定ハードコード。引数化しない）
さくら www/taskboard/ → iPhone（Basic認証）
```

- さくらの「国外IPアドレスフィルタ」は無効のまま維持（有効だと Actions からの FTPS が切断される）
- AIの実行環境は HTTPS(443) 以外の外向き通信不可。配信は必ず Actions 経由

## 3. 目標コード構成（確定済み）

リファクタリング後の姿。**この構成で書く。**

| ファイル | 責務 |
|---|---|
| `scripts/boardlib.py` | 共通ロジック：タスク読込（`load_tasks`／`parse_note`）、front matter 解析、lead 逆算、日付処理、節の振り分け（至急・今日やるつもり・待ち・1週間枠・期限アラート・監視・タイムライン対象・団体別）、定数（`THIS_WEEK_LIMIT=7` `LIGHT_LIMIT=10` `TIMELINE_DAYS=150` `AUTO_WEEK_DAYS=3` 団体色 等）、重複排除（`uniq`） |
| `scripts/gen_dashboard.py` | HTML描画のみ（CSS・行部品・タイムラインSVG・団体カード） |
| `scripts/gen_dashboard_md.py` | md描画のみ（Obsidianモバイルで確実に出る記法のみ。SVG・HTMLタグ不使用） |

**CLI引数と update.sh のインタフェースは従来と同一**：

    python3 scripts/gen_dashboard.py    <リポルート> <today yyyy/mm/dd> <out.html> [fixed.json]
    python3 scripts/gen_dashboard_md.py <リポルート> <today yyyy/mm/dd> <out.md>   [fixed.json]

現状は両スクリプトが読込〜分類ロジックを丸ごと複製している（改修時の二重修正が事故源）。
boardlib への集約が v1.0 後の最初の宿題。

## 4. データフロー

```
tasks/*.md ─ parse_note ─→ front matter dict の列
  │  先頭 --- ブロックを「key: value」で素朴に解析（YAMLパーサ不使用・ネスト不可）
  │  _ 始まりのファイルは無視。status: dropped は読込時点で除外。id でソート確定
  ↓
lead 逆算（親の due − lead 日 → 子の due を上書き。過去日なら lead_broken 警告）
  ↓
分類（仕様書§3・§5 の条件で各節のリストを作る）＋ children 索引（parent 逆引き）
  ↓
重複排除（uniq：上の節から順に shown_ids へ登録）
  ↓
描画（HTML または md）→ board/ へ書き出し
```

`config/fixed.json` は★付きカレンダー予定のスナップショット（`events` 配列）。
「2週間ある」にのみ使う。無ければ空扱いで動く。

## 5. 改修時の検証手順

生成は決定的（入力とtodayが同じなら出力が同じ。読込順は id ソートで確定済み）。
**基準出力との diff で回帰を検証する。**

1. 改修前のコードで基準を作る：
   `python3 scripts/gen_dashboard.py . 2026/08/18 /tmp/base.html config/fixed.json`（md版も同様）
2. 改修後に同じ引数で生成し比較：
   - HTML版：`diff /tmp/base.html /tmp/new.html`（完全一致が原則）
   - md版：**「生成:」行（時刻入り）を除いて比較**。
     `diff <(grep -v '^生成: ' /tmp/base.md) <(grep -v '^生成: ' /tmp/new.md)`
3. 表示仕様を意図的に変える改修では、diff の全行が意図した変更であることを目視確認
4. 最後に `scripts/update.sh` を通し、無変更時に「pushしません」で止まることも確認

today を固定して渡せるので、期限切れ・3日以内・14日境界・監視7日境界を跨ぐ日付で
数パターン回すとよい。

## 6. 変更してはいけない不変条件

- **生成物（`board/`）を手編集しない。** 直すのは `tasks/` か `scripts/`
- **語彙を増やさない。** `status` 7語・`reason` 3語・`wait` 2語は固定。新しい表現が要るときは
  増野さんと合意してから仕様書を先に改訂する
- **削除せず退避。** 不要物は `_to_delete/<理由>_YYYYMMDD/` へ
- **採番は1コミット**（numbering.json の +1 とファイル作成を分けない）
- **後方互換：既存キーの意味を変えない。** 196件の実データが正。キーの解釈を変える改修は
  全タスクの一括変換とセットでのみ行う
- CLI引数・update.sh のインタフェースを変えない（呼び出し側は増野さんの手とAIの型の両方）
- FTPS のアップ先 `www/taskboard` はYAMLハードコードのまま（さくらライトの唯一の防御線）
- 出力の決定性を壊さない（乱数・時刻依存・辞書順依存を分類ロジックに持ち込まない。
  時刻を書いてよいのは md版の「生成:」行だけ）

## 7. リポジトリ構成（要点）

| 場所 | 中身 |
|---|---|
| `tasks/` | 正本。全団体フラット。団体別フォルダを作らない（識別はID接頭辞） |
| `config/numbering.json` | 採番台帳（接頭辞ごとの `last`＝発行済み最大番号） |
| `config/recurring/<接頭辞>.md` | 定期タスク。`tasks/` に置くと名前衝突するため分離 |
| `config/fixed.json` | ★予定スナップショット |
| `board/` | 生成物（`index.html` / `taskboard.md`） |
| `archive/YYYY-MM/` | 完了タスクの月次退避先 |
| `docs/` | 本書・仕様書・経緯・実績ログ |
