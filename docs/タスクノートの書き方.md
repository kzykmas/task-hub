# タスクノートの書き方

`tasks/*.md` の front matter の仕様。実データ（196件）から起こしたもので、**ここに無いキーは増やさない**。

## front matter の全キー

| キー | 値 | 意味 |
|---|---|---|
| `id` | `GONO-130` 等 | 接頭辞＋3桁。人は番号を振らない（→採番） |
| `org` | 郷野の郷 / 構想P / STREAM / 安全学校 / AI改善 / 家族・個人 | ボードの色分けキー |
| `title` | 文 | タスク名 |
| `short` | 短縮名 | 親参照やタイムラインでの表示名。長いタイトルには付ける |
| `status` | 下記7語 | → status の節 |
| `role` | `do`（自分が実行）/ `monitor`（他人の担当をPMとして監視） | 無印は `do` |
| `due` | `2026/08/17` | 期日 |
| `size` | `light` のみ | 1時間未満の軽タスク。無印＝重（1時間以上の検討・調整・検証） |
| `labor` | `physical` | 肉体作業。💪で表示。1日1回を目安に頭脳作業へ織り交ぜる |
| `timebound` | `true` | 日時変更不可の拘束。期限アラートに出さず「2週間ある」で見る |
| `undated` | `true` | 拘束だが日付未定（枠だけ確保） |
| `urgent` | `true` または `2026/08/14` | 恒常的に至急／その日だけ至急。「明日に先送り」に使える |
| `today` | `2026/08/15` | **その日にやるつもり**。`🎯 今日やるつもり` 節に出る。日付なので翌日には自動で外れる。`urgent`（やらねばならない）とは別の、自分で決めた枠 |
| `later` | `true` | あとで。**`あとで` と書くと効かない**（`true` 以外は無視される） |
| `reason` | `法令期限` `安全` `資金` | **この3語だけ**色付きチップになる。他を書いても表示されない |
| `parent` | `KOSO-001` | 親タスクのID |
| `lead` | `3d` | 親の `due` から逆算して自分の `due` を**上書きする**。逆算切れは警告が出る |
| `owner` | 人名 | 相手の作業。タイムラインで破線バー＋担当名 |
| `asked` | 日付 | 依頼日。「待ちN日目」の起点。**未記入だと「未依頼」と赤字**で出る |
| `next_check` | 日付 | `role: monitor` 用。7日以内に来ると「監視の期日」に出る |
| `check_cycle` | `monthly` / `weekly` / `daily` | 見回りの周期。`daily` は開催直前の集客チェック等（確認したら `next_check` を翌日へ進める） |
| `wait` | `important` / `light` | `status: waiting` のときの重要度。**無印は自動判定**（期限の1週間前を切ったら重要）。→ `👥 待ち` の節 |
| `pin` | `true` | タイムラインの**最上位に固定**する。期日が先でも常に目に入れたい手続き用（例：GONO-006 の法令期限） |
| `src_no` | `A-09` 等 | 郷野の郷の元台帳の番号。**あればIDの代わりに表示される** |
| `category` / `category_name` | `A`〜`H` / 運営手続き 等 | 元台帳の分類 |
| `project` | フォルダ名 | 関連する企画フォルダ |
| `created` / `done_date` | 日付 | 起票日／完了日 |

本文は `## 概要` `## 経緯` を基本とし、必要に応じて `## 要確認` `## 完了` を足す。
**経緯には日付と誰の指示かを書く**（例：`- 2026/08/14 増野さん報告により完了`）。

## status の挙動（スクリプトが実際に何をするか）

| 値 | 挙動 |
|---|---|
| `todo` | 既定。期限アラート・団体別ボードに出る |
| `this_week` | **「これから1週間でやる」に出る唯一の値。重タスクは7枚が上限**（`size: light` は別枠で10件目安） |
| `doing` | 仕掛かり中。**節は作らず、行の左に 🚧 マークが付く**（💪と同じ扱い。2026/08/15 決定）。集計上は `todo` と同じ |
| `research` | **事前調査**（仕掛かる前の壁打ち・整理）。行の左に 🔍。集計上は `todo` と同じ。`doing` と分けるのは、**着手していないものを進捗に数えないため**（2026/08/15 決定） |
| `waiting` | 相手の作業・納品待ち。**期限アラートに出さず `👥 待ち` 節に出る**（自分が動けないタスクを急かさないため。2026/08/14 決定） |
| `done` | 全ての集計から外れる。月次で `archive/YYYY-MM/` へ移す |
| `dropped` | 読み込み時点で除外される |

「至急 — 今日やる」に出るのは、`done` `waiting` 以外で、`due` が今日 または `urgent` が今日のもの。
「今日やるつもり」に出るのは、`done` `dropped` 以外で、`today` が今日のもの。

**上部の節は重複しない**（2026/08/15 決定）。1つのタスクは

    至急 → 今日やるつもり → 待ち → 今週（重）→ 今週（軽）→ 期限アラート → 監視の期日

の順で**最初に該当した1節にだけ**出る。同じタスクが何度も現れると、今日やる量が実際より
多く見えるため。省かれた分は見出し脇に「（＋上の節に N件）」と出る。
**「2週間ある」は対象外**（カレンダー＝事実の枠。日付が抜けると誤読される）。
**「タイムライン」「団体別ボード」も対象外**（全体を俯瞰する場所なので重複してよい）。

なお「これから1週間でやる」の件数（N/7）は**枠の総数のまま**で、重複排除では減らない。
7枚制限は意思の枠であって、表示件数ではないため。

## 採番

1. `config/numbering.json` の該当接頭辞の `last` を読む
2. +1 した番号でファイルを作る（`<接頭辞>-<3桁>_<タイトル>.md`）
3. `last` を更新する
4. **以上を1コミットで行う**

人は番号を振らない。push が reject されたら `pull --rebase` 後に採番し直す。
接頭辞は AIW（AI改善）/ GONO（郷野の郷）/ STRM（STREAM）/ KOSO（構想P）/ ANZN（安全学校）/ ME（家族・個人）。

**ID重複は過去に起きている**（2026/08/14 に STRM-010 の重複を解消）。
直すときは「番号の若い方を残す」より**生きているタスクのIDを変えない**ことを優先する。
退避は削除せず `_to_delete/<理由>_YYYYMMDD/` へ。

## やってはいけないこと

- 生成物（`board/`）の手編集。直すのは `tasks/` か `scripts/`
- 語彙を勝手に増やす（上の表に無い `status` や `reason` を作らない）
- 入力に無い情報を書く。不足は質問する
- ファイルの削除（`_to_delete/` へ退避する）

## 👥 待ち の重要度（2026/08/16）

毎朝まずチェックする節なので、`👥 待ち` は **「今日やるつもり」の直下**に置き、
中を**重要**と**軽度**に分けて見た目のトーンを変える（軽度は薄く表示）。

| 指定 | 挙動 |
|---|---|
| `wait: important` | 常に重要 |
| `wait: light` | 常に軽度 |
| 無印 | **期限の1週間前を切ったら重要**、それより先なら軽度（自動で切り替わる） |

「期限が近づいたら自然に浮かび上がる」ことを既定にし、それに当てはまらないものだけ明示する。
