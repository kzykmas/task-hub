# リポジトリ構成と配信の仕組み

## フォルダ

| 場所 | 中身 |
|---|---|
| `tasks/` | ★正本。全団体フラット196件（`GONO-128.md` `STRM-011.md` …） |
| `config/numbering.json` | 採番台帳。接頭辞ごとの `last` |
| `config/recurring/<接頭辞>.md` | 各団体の定期タスク（旧 `_定期.md`）。`tasks/` に置くと6団体で名前が衝突するため分離 |
| `config/fixed.json` | ★付きカレンダー予定のスナップショット |
| `scripts/` | `gen_dashboard.py`（HTML）／`gen_dashboard_md.py`（md）／`update.sh` |
| `board/` | 生成物。`index.html`（本番ボード）と `taskboard.md`（モバイル簡易版） |
| `archive/YYYY-MM/` | 完了タスクを月次で移す |
| `docs/` | 本書と `タスクノートの書き方.md` |

`tasks/` は**フラット**（団体別フォルダを作らない）。ID接頭辞で識別でき、団体追加は
`numbering.json` に1行足すだけ。何より **Vault の団体フォルダと同じ見た目にしない**ことが
「どっちが正本か」の再発を防ぐ。団体別の絞り込みはボード側で行う。

## 3層分離

**正本＝GitHub（このリポ）／配信＝さくら／知識・資料＝Obsidian Vault。**
Vault にタスクの正本はもう無い（2026/08/14 に移行、全207ファイルmd5一致で検証済み）。
**端末側で git を動かすのはこのリポだけ。Vault に `.git` は置かない**（Obsidian Sync と競合するため）。

## 生成と配信

```
scripts/update.sh "メッセージ"
  ├ git pull --rebase --autostash      # AIが編集した直後でも止まらないよう autostash が必須
  ├ python3 scripts/gen_dashboard.py    . <today> board/index.html   config/fixed.json
  ├ python3 scripts/gen_dashboard_md.py . <today> board/taskboard.md config/fixed.json
  ├ 実質無変更なら何もしない            # md版は生成時刻を毎回書くため、それだけの差分は無視する
  └ git commit && git push (main)
        ↓
.github/workflows/deploy-sakura.yml    # board/** への push で発火
        ↓ FTPS
さくら www/taskboard/  →  iPhone（Basic認証）
```

- アップロード先 `www/taskboard` は YAML に**固定でハードコード**する（引数化しない）。
  さくらライトは専用FTPアカウントを作れずサーバーパスワードがサーバー全体に及ぶため、これが唯一の防御線
- **さくらの「国外IPアドレスフィルタ」は無効にしてある**。有効だとGitHub Actions（米国）からのFTPが
  `PASS` 直後に無言で切断され `curl exit 56` になる。復活させたい場合は配信方式の変更が要る

## 秘書セッションの動かし方

デスクトップアプリの **Code タブ**で、フォルダに `~/Claude/Projects/repos/task-hub` を追加し、
**ローカル環境**でセッションを開始する。ローカルなら増野さん自身の git 認証を使うため
**main へ直接 push できる**（クラウド環境は `claude/` ブランチ＋PR になる可能性があり未検証）。

**Cowork からはこのリポに push できない**（git proxy が 403。clone は通るので誤認しやすい）。
タスク管理を Cowork でやろうとしないこと。
