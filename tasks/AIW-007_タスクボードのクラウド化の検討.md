# AIW-007 タスクボードのクラウド化の検討

## 課題（なぜ必要になったか）
移動中・仕事中に**スマホからタスクの修正や追加**が発生することが増えた。
いまの構成は**正本がローカルPC（Mac）のVault**にあるため、次の詰まりが出ている。

1. **Macが起きていないと書き戻せない** — 2026/08/11 に実際に**2回**発生。
   デバイスブリッジが切断し、KOSO-031やAIW-007の変更をVaultへ反映できなかった
2. **スマホから直接タスクを触れない** — Coworkセッション経由でしか編集できず、
   そのCoworkもMacが繋がっていないと正本に届かない
3. 複数の入り口（Mac・Cowork・事務所PC）から触ると**同期が取れない**
4. **ID採番の衝突**が起きる — 2026/08/11、増野さんがVault側で作ったAIW-006と、
   Cowork側で採番したAIW-006がぶつかった（本タスクをAIW-007へ振り直し）。
   正本が一つでないと採番の一意性が保てない

## 選択肢

### A. Git（GitHubプライベートリポジトリ）を正本にする ★本命候補
- Vault（少なくとも各 `tasks/`）をgit管理し、GitHubへプッシュ
- **Coworkセッションから直接 clone / commit / push できる**（Macの起動が不要になる）
- Mac側は `git pull` で同期。**Obsidianはそのまま使える**（ファイルはMarkdownのまま）
- 事務所のClaude Codeからも**同じリポジトリ**を触れる
- 変更履歴が全部残るので、いまの `_to_delete/` 退避運用が不要になる
- スマホからはGitHubのWeb/アプリで直接編集も一応可能

**検討ポイント**
- 必ず **private**（団体・個人情報が入るため）
- 対象は**Vault全体か `tasks/` だけか**（Vaultには他の資料も多い）
- Mac・クラウド双方で同じファイルを触ったときの**コンフリクト処理**をどうするか
- 認証（PAT or SSH）をCowork側にどう持たせるか
- **採番の一意性**をどう担保するか（pull前提の運用ルール or 採番をスクリプト化）

### B. Obsidian Sync / iCloud / Google Drive でファイル同期
- Obsidian Syncは公式・モバイルアプリありで**スマホから直接編集できる**
- ただし**Coworkからは触れない**ため、デバイスブリッジ依存が残り課題1が解決しない
- Google Driveなら Cowork の Google Drive MCP で読める（現セッションで利用可）が、
  書き込みと競合解決が弱い

### C. 外部SaaSへ移行（Notion / Todoist / Google Tasks 等）
- スマホ体験は最良。MCP連携もある
- ただし**1タスク1ノート＋frontmatter＋自作スクリプトの資産を捨てる**ことになる
- 重/軽・頭脳/肉体・lead逆算・負荷スコア・★規約といった独自設計を再現しづらい
- → 今の設計への投資量を考えると割に合わない見込み

### D. 事務所のClaude Codeを常時起動＋定時実行
- 事務所PCが常時オンなら、そこが同期と自動生成のハブになる
- ただし単体では「PCが起きていないと駄目」という**根本問題が移動するだけ**
- **Aと組み合わせると有効**（毎朝 pull → ダッシュボード生成 → 配信）

## 現時点の見立て（AI推測）
**A（GitHub private）を土台にし、Dで自動化**が本命。
理由は、いまの設計・スクリプト・ノート資産をそのまま活かしたまま、
「Macが起きていないと詰まる」という一番の痛点だけを外せるため。

**+α**：ダッシュボードHTMLを**GitHub Pages**に置けば、URLで**いつでも最新版**が見られる。
以前に出た「ローカルで開けば常に最新か？」という疑問への答えにもなる。
さらにGitHub Actionsで毎朝自動生成すれば、AIW-004（毎朝定時更新）とも合流できる。

**スマホからの入力導線**は、GitHubアプリで直接ファイルを編集するより、
**スマホのCoworkに話しかけてAIがcommitする**方が現実的（いまの使い方の延長になる）。

## 保管場所の役割分担（2026/08/11 調査で確定した見立て）

**クラウド実行でも Google Drive / Googleカレンダーは使える**。
Claude Code on the web のセッションでは **claude.ai のコネクタがリモートホスト側から
提供される**（`--mcp-config` として渡る）。どのコネクタを使えるかは claude.ai の組織設定で管理する。
→ **Macが起きていなくてもDriveとカレンダーには届く**。実際、本セッションでも
   Googleカレンダー18本の走査はMacを介さずクラウドから実行できている。

つまり **Macが落ちて困るのはローカルVaultだけ**。そこだけを外へ出せばよい。

| 置くもの | 置き場 | 理由 |
|---|---|---|
| **tasks/ のMarkdown・設計書・ログ** | **GitHub private** | 差分・履歴・採番の一意性。Claude Code webが**cloneできるのはGitHubだけ** |
| **オフィス系ファイル・成果物（xlsx/docx/pptx/PDF等）** | **Google Drive のまま** | バイナリはgit向きでない。コネクタ経由でクラウドから読める |
| **共有予定** | **Googleカレンダー のまま** | 他者との共有が本来の役割（AIW-009 論点1） |

補足：`.mcp.json` をリポジトリにコミットしておけば、
**クラウドセッションはプロジェクトスコープのMCPサーバーを自動で読み込む**（確認を求められない）。
移行時はこれで接続設定ごとリポジトリに載せられる。

## ⚠ D案の訂正（2026/08/11 追加調査）
当初「**A（GitHub）＋D（事務所PC常時起動で定時実行）**」を本命としたが、
**Claude Code on the web に Routines（定時実行）がある**ため、
**毎朝の自動更新はクラウド側で完結する**。
→ **D は不要**。「常駐PCを置く」という発想自体が、
   「PCが起きていないと詰まる」という当初の課題を持ち込み直すことになる。
**結論は A 単独（＋クラウド側のRoutines）** に修正する。

## AIW-008（実行環境の見直し）との関係
**本タスクがAIW-008の前提条件**。Claude Code on the web は
**リポジトリのcloneとPR作成にGitHubが必要**なため、
ここでA（GitHub private）を選べば、そのままClaude Code webへ移行できる。
逆にB/Cを選ぶとAIW-008の選択肢が狭まる。**2件は同じ回で判断するのが効率的**。
