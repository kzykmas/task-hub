# AIW-008 実行環境の見直し（デスクトップアプリ不調とClaude Codeリモートへの移行）

## 症状（増野さん報告・2026/08/11）
1. **再ログインを頻繁に求められる** — 体感で**2日に1回程度**
2. **アプリが重い・画面がなかなか出ない** — **3〜5秒**待つと、別のセッションを開くような挙動になる

いずれもClaudeデスクトップアプリ（Mac）。Cowork中心の使い方で顕在化している。

## 調べたこと（2026/08/11時点）
- **再認証が頻発する事象は他でも報告がある**（anthropics/claude-code の Issue #28302
  「Frequent re-authentication required」など）。またSSOログイン関連の障害履歴も status ページにある
  → まず **status.claude.com** を確認し、続いていれば**アプリのアップデート**と
    **サインアウト→サインイン**をやり直す。それでも直らなければサポートへ報告
- 表示の遅さは、**セッションが溜まっていること**が影響している可能性がある
  → 古いセッションのアーカイブ／削除を試す価値あり

## 本題：Claude Code（リモート）へ寄せるか

### 分かっていること（公式ドキュメント確認済み）
- **Claude Code on the web**（claude.ai/code）は **Anthropic管理のクラウドで実行**され、
  **ブラウザとClaudeモバイルアプリから使える**。ブラウザを閉じてもセッションは継続する
  → **デスクトップアプリに依存しない**ので、上記の症状を丸ごと回避できる
- 現在 **research preview**（Pro / Max / Team 向け）
- **定時実行（Routines）**が使える → AIW-004（毎朝の自動更新）と合流できる
- ⚠ **リポジトリのcloneとPR作成にはGitHubが必要**。GitHub以外はローカルからバンドル送信できるが
  **結果をリモートへ push し返せない**
- レート上限は他のClaude利用と共有

### つまり
**AIW-007（GitHub化）がAIW-008の前提条件**になる。
Vaultの `tasks/` をGitHub privateに置けば、Claude Code on the web から
**ブラウザ／スマホで直接タスクを編集・commitできる**。
デスクトップアプリのブリッジも、Macの起動も要らなくなる。

順番としては **AIW-007（GitHub化）→ AIW-008（Claude Code webへ移行）** が自然。

### 残る論点
- Coworkの使い勝手（会話でざっくり指示する運用）とClaude Codeの操作感の差
- Coworkにしかない機能（アーティファクト表示・デバイスブリッジ）をどこまで手放せるか
- 事務所のClaude Codeを「ローカル実行の拠点」として残すか、完全にクラウドへ寄せるか
- Google カレンダー連携（★予定の取得）が移行後も同じようにできるか **←要確認**

## 事務所の常駐PC（MBA2020）は要るか（2026/08/11 検討）

**Claude Codeの実行環境としては不要になる。**
- クラウドセッションは**Anthropicのクラウドで実行**され、ブラウザ／スマホは**ただのクライアント**
- **Routines（定時実行）もクラウド側**にある → 常駐させて毎朝走らせる必要がない
- Remote Control / Dispatch は「自分のマシンを動かす」方式なので、
  そもそも乗り換えの目的（**PCが起きていなくても回る**）と逆行する

**ただし端末そのものが要らなくなるわけではない。** 残る用途：
- **Obsidianで見る・書く端末**（git pull してVaultを手元に持つ）
- **事務所モードの大画面**（ただしブラウザが動けばよく、性能は要らない）
- **ローカルにしか置けない資料・印刷など物理的な作業**

⚠ **クラウドセッションはローカルファイルにも localhost にも届かない。**
ローカルにしか置けないものが残る場合、そこだけ Remote Control を使う選択肢は残る。
→ **「ローカルにしか無いもの」を洗い出すのが、この判断の前提作業**。
