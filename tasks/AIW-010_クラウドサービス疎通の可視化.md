# AIW-010 クラウドサービス疎通の可視化

## 目的
業務中に、利用中のクラウドサービスへ正常に繋がっているか（疎通できるか）を常に可視化し、**不具合の早期発見**につなげる。
背景：これまで K1（Macを閉じるとデバイスブリッジ経由のVault書き戻しが不能になる）や K12（接続不調）のように、**繋がっていないことに気づかないまま作業が空振りする**トラブルが繰り返し起きてきた。疎通状態が目に見えていれば、原因切り分けの初動が速くなる。

## 対象サービス（5つ）
1. デバイスブリッジ / Vault（Cowork接続先のMac — MBA2020常駐化案は置き場整理§3-7）
2. Google Drive
3. Googleカレンダー
4. GitHub（task-hub）
5. さくら（配信面）

## 方式案
- **ダッシュボード生成時のヘルスチェック**：ボード生成スクリプトの冒頭で各サービスに軽い読み取りアクセスを行い、結果を**ボード上部の状態行（🟢正常／🟡遅延・一部不調／🔴不通）**として表示する。ボードは毎回生成されるため、追加の常駐プロセスなしで「最後に生成した時点の健全性」が常に目に入る。
- **将来**：Routines（スケジュールタスク）での**定期チェック**に発展させ、生成タイミングに依存しない監視とする。異常時の通知方法もそこで検討。

## 位置づけ
- AIW-009（グランドデザイン見直し）の細目。方針の出典は `20260813_仕事環境の置き場整理.md` §7。
- 実装は **AIW-007 の P2/P3（生成スクリプトのクラウド化・配信整備）と合流**して行う。P2/P3で生成パイプラインが確定した後、その中にヘルスチェックを組み込むのが最小コスト。

## 進め方
1. [ ] 各サービスの疎通確認方法（軽量な読み取りAPI/コマンド）を洗い出す
2. [ ] 状態行の表示仕様（🟢🟡🔴の判定基準・表示位置）を決める
3. [ ] AIW-007 P2/P3の生成スクリプトに組み込む
4. [ ] 運用してみて、Routinesでの定期チェック化を判断
